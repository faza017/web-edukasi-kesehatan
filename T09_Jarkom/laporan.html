1. Pendahuluan

Tugas ini bertujuan merancang dan menyimulasikan jaringan multi-router yang menggabungkan segmen LAN kabel dan LAN nirkabel. Pengalamatan dirancang dengan teknik Variable Length Subnet Mask (VLSM), seluruh client memperoleh alamat IP secara otomatis dari sebuah DHCP Server terpusat, dan konektivitas antar-router diuji dalam dua skenario: Kasus A menggunakan routing statis + default route, dan Kasus B menggunakan protokol routing dinamis OSPF Area 0. Keberhasilan diukur dengan uji ping dan tracert dari Laptop nirkabel ke PC kabel hingga mencapai 100% Reply.

Simulasi dibuat pada Cisco Packet Tracer 9.0.1 dan disimpan dalam dua berkas: KasusA_Static.pkt dan KasusB_OSPF.pkt.

4. Konfigurasi DHCP Server dan DHCP Relay

Server diberi IP statis 192.168.10.130/26 dan layanan DHCP diaktifkan dengan dua pool:

PoolDefault GatewayDNSStart IPSubnet MaskMax User
LAN_KABEL (serverPool)192.168.10.129192.168.10.130192.168.10.140255.255.255.19250
LAN_WIFI192.168.10.1192.168.10.130192.168.10.10255.255.255.128100

Client pada LAN kabel berada pada broadcast domain yang sama dengan server sehingga paket DHCPDISCOVER langsung diterima server. Client nirkabel berada di subnet lain; karena router tidak meneruskan broadcast, interface R2 Gig0/0 dikonfigurasi ip helper-address 192.168.10.130. R2 bertindak sebagai DHCP Relay Agent: mengubah broadcast DHCP menjadi unicast ke server dan mengisi field giaddr = 192.168.10.1. Berdasarkan giaddr tersebut server memilih pool LAN_WIFI. Proses DORA (Discover–Offer–Request–Acknowledge) lintas router ini hanya berhasil jika routing R1↔R2 sudah benar, sehingga keberhasilan DHCP pada client nirkabel sekaligus menjadi indikator awal bahwa routing berfungsi.

4.1 Konfigurasi Wireless

AP1 dikonfigurasi dengan SSID T09_WIFI, autentikasi WPA2-PSK (enkripsi AES), passphrase itera2026. Modul jaringan bawaan Laptop-PT diganti dengan kartu wireless WPC300N. Laptop1, Laptop2 dan Smartphone diatur menggunakan SSID dan kunci yang sama dengan mode IP DHCP. AP-PT bekerja sebagai bridge Layer 2, sehingga client nirkabel berada pada subnet 192.168.10.0/25 milik R2.

5. Kasus A – Routing Statis dan Default Route

R1 berada di sisi pusat (LAN kabel + server) dan diberi static route spesifik menuju LAN nirkabel. R2 berperan sebagai router cabang (stub) yang hanya memiliki satu jalur keluar, sehingga cukup diberi default route (0.0.0.0/0) menuju R1.

6. Kasus B – OSPF Single Area (Area 0)

Static route dan default route Kasus A dihapus, lalu kedua router menjalankan OSPF proses 1 dengan seluruh network dimasukkan ke Area 0 (backbone). Router-ID ditetapkan manual (1.1.1.1 dan 2.2.2.2). Interface LAN dijadikan passive-interface agar Hello OSPF tidak dikirim ke client (lebih aman dan hemat), namun subnetnya tetap diiklankan.

6.1 Konfigurasi R1

! ===== R1 - KASUS B : GANTI STATIC ROUTE DENGAN OSPF AREA 0 =====
enable
configure terminal
! 1) Hapus static route Kasus A
no ip route 192.168.10.0 255.255.255.128 192.168.10.194
!
! 2) Aktifkan OSPF
router ospf 1
 router-id 1.1.1.1
 network 192.168.10.128 0.0.0.63 area 0
 network 192.168.10.192 0.0.0.3 area 0
 passive-interface GigabitEthernet0/0
 exit
!
end
write memory
!
! Verifikasi:
! show ip ospf neighbor
! show ip route
! show ip protocols

7.1 Pembahasan

Kinerja data plane sama. Pada topologi dua router dengan satu link, kedua metode menghasilkan jalur forwarding yang persis sama; ping dan traceroute tidak menunjukkan perbedaan hop maupun latensi yang berarti. Perbedaan utamanya ada di control plane.

Default route efisien untuk stub. R2 hanya punya satu jalan keluar, sehingga satu baris default route sudah mencakup semua tujuan, termasuk subnet yang ditambahkan di sisi R1 kelak. Namun R1 tetap memerlukan static route spesifik ke LAN nirkabel, dan setiap penambahan subnet di sisi R2 menuntut perubahan manual di R1 – rawan kesalahan ketik (misalnya salah mask/next-hop) yang menyebabkan blackhole.

OSPF unggul dalam otomasi dan skalabilitas. Dengan OSPF, setiap router cukup mengumumkan network miliknya; rute ke subnet lain muncul otomatis. Bila nantinya ditambahkan router ketiga atau link cadangan, OSPF akan memilih jalur dengan cost terkecil dan melakukan failover otomatis, sesuatu yang tidak dapat dilakukan static route biasa (kecuali dengan floating static route). Biayanya berupa trafik Hello/LSA dan konsumsi CPU/memori untuk SPF, yang pada skala tugas ini dapat diabaikan.

Catatan saat migrasi. Static route harus dihapus terlebih dulu; jika dibiarkan, rute statis (AD 1) akan selalu mengalahkan rute OSPF (AD 110) sehingga OSPF tidak terlihat dipakai di tabel routing.

8. Kesimpulan

  1. Teknik VLSM berhasil membagi blok 192.168.10.0/24 menjadi subnet /25 (LAN nirkabel), /26 (LAN kabel) dan /30 (link P2P) secara efisien dengan sisa 60 alamat cadangan.
  2. Seluruh client kabel maupun nirkabel memperoleh IP otomatis dari satu DHCP Server terpusat; client di subnet berbeda dilayani melalui DHCP relay (ip helper-address) di R2.
  3. Kasus A (static + default route) dan Kasus B (OSPF Area 0) sama-sama menghasilkan konektivitas 100% Reply dari Laptop nirkabel ke PC kabel dengan jalur 3 hop yang identik.
  4. Routing statis lebih sederhana dan tanpa overhead, cocok untuk jaringan kecil/stub, sedangkan OSPF lebih skalabel, adaptif terhadap perubahan topologi, dan minim konfigurasi manual saat jaringan bertambah besar.
